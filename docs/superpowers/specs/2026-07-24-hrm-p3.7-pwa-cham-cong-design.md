# P3.7 — Đóng gói PWA riêng cho vỏ chấm công (`/toi`)

**Ngày:** 2026-07-24
**Nhánh:** feat/hrm-p3.1-cham-cong-thuc-te
**Trạng thái:** Design đã duyệt, chờ viết plan

## 1. Mục tiêu

Cho phép nhân viên **cài vỏ chấm công `/toi` thành một app PWA riêng** (tên "Chấm công",
mở thẳng màn check-in) trên điện thoại, đồng thời **giữ nguyên** app PWA "Nhân sự" hiện có
cho admin cài từ `/`. Cùng một codebase, cùng một build, cùng một deploy — không tách
subdomain, không thêm hạ tầng.

**Yêu cầu định hướng (quan trọng):** sau này vỏ chấm công sẽ được **bọc Capacitor** thành app
native (App Store / Google Play). Vì vậy phase này KHÔNG chỉ làm PWA web, mà phải để sẵn các
"đường may" (seams) để về sau bọc Capacitor chỉ là thêm lớp vỏ, **không phải sửa lại logic
app**. Xem §7. Việc thêm Capacitor thực sự (native project) nằm ở phase sau; phase này chỉ
chuẩn bị mã để dễ bọc.

## 2. Bối cảnh hiện trạng

- Repo là **một SPA / một PWA duy nhất**. `fe/vite.config.ts` dùng `vite-plugin-pwa` với
  một manifest: `name: "Nhân sự"`, `start_url: "/"`, `scope: "/"`, `theme_color: #1F3864`,
  icon `pwa-192x192.png` / `pwa-512x512.png`.
- `fe/index.html` **không có** thẻ `<link rel="manifest">` cứng — plugin tự chèn manifest
  "Nhân sự" lúc build.
- Service worker đăng ký **thủ công** qua `src/components/shared/PWAUpdatePrompt.tsx`
  (`virtual:pwa-register`, `injectRegister: false`, `registerType: "prompt"`). SW scope `/`,
  phủ luôn `/toi`.
- Cache: app shell precache + SPA fallback `/index.html`; API là **NetworkOnly** (không cache).
- Vỏ nhân viên đã tồn tại ở route `/toi` (`EmployeeLayout`): `cham-cong` (check-in),
  `don-tu`, `bang-cong`, `tai-khoan`, và `/toi/login` (`DangNhapChamCongPage`). Route `/toi`
  index redirect sang `cham-cong`.

**Ràng buộc kỹ thuật cốt lõi:** một build của `vite-plugin-pwa` chỉ sinh **một** manifest.
Muốn có app cài đặt thứ hai phải cung cấp manifest thứ hai theo cách khác và trỏ tài liệu
tới nó khi phù hợp.

## 3. Giải pháp: manifest thứ hai + tráo link theo route

### 3.1 Manifest tĩnh thứ hai

Thêm file `fe/public/manifest.chamcong.webmanifest` (copy nguyên trạng vào `dist/` khi build):

```json
{
  "name": "Chấm công",
  "short_name": "Chấm công",
  "description": "Chấm công nhân viên",
  "lang": "vi",
  "id": "/toi",
  "start_url": "/toi/cham-cong",
  "scope": "/toi",
  "display": "standalone",
  "orientation": "portrait",
  "theme_color": "#1F3864",
  "background_color": "#ffffff",
  "icons": [
    { "src": "/pwa-192x192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/pwa-512x512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/pwa-512x512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

- `id: "/toi"` khác `id: "/"` của app "Nhân sự" (mặc định `id = start_url`) → Chrome coi là
  **hai app cài đặt riêng biệt** trên cùng origin, không ghi đè nhau.
- `scope: "/toi"` → app chấm công cô lập trong `/toi` (bao gồm cả `/toi/login`); link ra
  ngoài `/toi` mở ở trình duyệt hệ thống.
- `start_url: "/toi/cham-cong"` → mở thẳng màn check-in. Nếu chưa đăng nhập, ProtectedRoute
  của `/toi` tự đẩy sang `/toi/login` (vẫn trong scope).
- Icon/theme dùng lại tài nguyên hiện có (theo quyết định: tạm dùng chung icon).

> Không dùng `vite-plugin-pwa` để sinh manifest này (plugin chỉ hỗ trợ một manifest). File
> tĩnh là nguồn sự thật cho manifest chấm công.

### 3.2 Module tráo link manifest

Thêm `fe/src/pwa/employeeManifest.ts`:

- Export `applyManifestForPath(pathname: string): void`.
- Nếu `pathname` bắt đầu bằng `/toi`:
  - Set `<link rel="manifest">` href = `/manifest.chamcong.webmanifest`.
  - Set meta `apple-mobile-web-app-title` = `"Chấm công"` (iOS đọc meta này làm tên khi
    "Add to Home Screen").
- Ngược lại (mọi path khác):
  - Khôi phục href = `/manifest.webmanifest` (manifest "Nhân sự" mặc định do plugin sinh).
  - Set meta `apple-mobile-web-app-title` = `"Nhân sự"`.
- Nếu thẻ `<link rel="manifest">` hoặc meta apple title chưa tồn tại (ví dụ môi trường dev)
  thì **tạo mới** rồi mới set — hàm không được ném lỗi khi thiếu thẻ.
- Thao tác thuần DOM, idempotent (gọi nhiều lần với cùng path cho cùng kết quả).

### 3.3 Đấu nối

- Gọi `applyManifestForPath(window.location.pathname)` **ngay đầu** `src/main.tsx` (trước khi
  render) để lần load trực tiếp vào `/toi/...` đã có manifest đúng.
- Thêm cập nhật theo điều hướng client-side: một effect nhỏ (trong `App.tsx` hoặc component
  con dùng `useLocation`) gọi `applyManifestForPath(location.pathname)` mỗi khi `pathname`
  đổi, để chuyển `/` ↔ `/toi` trong SPA cũng tráo manifest đúng.

### 3.5 App-target & boot thẳng vào chấm công (seam cho Capacitor)

Thêm `fe/src/appTarget.ts` — nguồn sự thật cho "app này đang chạy ở dạng nào":

```ts
export type AppTarget = "full" | "cham-cong";
export const APP_TARGET: AppTarget =
  (import.meta.env.VITE_APP_TARGET as AppTarget) ?? "full";
export const isChamCongApp = APP_TARGET === "cham-cong";
export function getHomePath(): string {
  return isChamCongApp ? "/toi/cham-cong" : "/";
}
// Nhận biết đang chạy trong Capacitor native (an toàn khi chưa cài Capacitor).
export function isNativeApp(): boolean {
  const cap = (globalThis as any)?.Capacitor;
  return !!cap?.isNativePlatform?.();
}
```

- Build web bình thường: `VITE_APP_TARGET` không set → `"full"` → mọi thứ y như hiện tại.
- Build để bọc Capacitor: chạy `VITE_APP_TARGET=cham-cong npm run build` → app biết mình là
  "app chấm công" và boot thẳng vào `/toi/cham-cong`.

Đấu nối trong `App.tsx`:
- Route index `/` và catch-all: **khi `isChamCongApp`**, redirect `/` (và các path admin)
  về `getHomePath()`. Nhờ đó webview Capacitor load `index.html` ở gốc `/` sẽ tự nhảy vào
  màn check-in mà không cần webview hỗ trợ initial-path.
- Khi `full`: giữ nguyên hành vi (`/` → `TrangChuTheoQuyen`).

### 3.6 Tắt service worker trong native (seam cho Capacitor)

- Bọc phần đăng ký SW (`PWAUpdatePrompt` / `registerSW` qua `virtual:pwa-register`) bằng điều
  kiện `!isNativeApp()`. Trong Capacitor, asset được phục vụ offline bởi native nên **không
  đăng ký SW** (tránh xung đột cache/scheme). Trên web thì không đổi gì.

### 3.7 Không đụng tới

- Cấu hình `vite-plugin-pwa`, service worker (web), chiến lược cache (API vẫn NetworkOnly).
- Manifest "Nhân sự" mặc định, luồng cập nhật `PWAUpdatePrompt` trên web.
- Logic đăng nhập, route con của `/toi`, `EmployeeLayout`.
- **Không** thêm offline queue cho check-in (ngoài phạm vi).
- **Không** tạo project Capacitor / native trong phase này — chỉ để sẵn seam.

## 5. Rủi ro & lưu ý

- **Tráo manifest runtime là kỹ thuật phía client:** trình duyệt đọc manifest lúc người dùng
  chủ động cài. Vì nhân viên vào app qua URL `/toi` (bookmark/link) nên path lúc load đã đúng;
  effect theo route xử lý trường hợp điều hướng nội bộ. Trong native Capacitor, manifest không
  được dùng (§6) nên module này chỉ chạy vô hại.
- **`manifest.chamcong.webmanifest` không được precache mặc định** (`globPatterns` không gồm
  `webmanifest`). Chấp nhận được vì manifest chỉ cần khi cài (online). YAGNI, không thêm.
- Hai app web cùng origin dùng chung một service worker (scope `/`) — đúng ý, app shell của
  `/toi` vẫn chạy offline như hiện tại.

## 6. Sẵn sàng bọc Capacitor (làm ở phase sau, spec này chỉ để seam)

Khi bọc Capacitor sau này, dự kiến chỉ cần **thêm vỏ**, nhờ các seam đã đặt ở phase này:

1. **Build một mục đích:** `VITE_APP_TARGET=cham-cong npm run build` → `dist/` boot thẳng vào
   `/toi/cham-cong` (§3.5). Đây chính là `webDir` cho Capacitor.
2. **Không có origin web thật:** trong native, tên/icon/splash lấy từ `capacitor.config.ts`
   + tài nguyên Android/iOS — **không dùng web manifest**. Manifest-swap (§3.2) tự vô hại vì
   native không cài PWA.
3. **Service worker tắt trong native** (§3.6) qua `isNativeApp()` → tránh xung đột scheme
   `capacitor://` với Workbox.
4. **API URL phải trỏ backend thật:** đã env-driven qua `VITE_API_BASE_URL`
   (`fe/.env.production`). Trong native, `localhost` không dùng được → build native phải set
   base URL tuyệt đối tới domain backend. Không cần đổi mã, chỉ cấu hình khi build.
5. **Asset base:** Capacitor phục vụ bundle ở gốc scheme nên đường dẫn tuyệt đối `/assets/...`
   vẫn ok; nếu native báo lỗi tải asset thì cân nhắc `base: "./"` khi build native — **ghi
   nhận, chưa làm** ở phase này.

Những việc thuộc phase Capacitor (KHÔNG làm bây giờ): thêm `@capacitor/core` + `@capacitor/cli`,
`npx cap add ios/android`, cấu hình `appId`/`appName`/splash/permission (camera, GPS cho
check-in), signing & store. Spec riêng sẽ mô tả.
